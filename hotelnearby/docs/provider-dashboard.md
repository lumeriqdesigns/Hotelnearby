# Provider dashboard (Prompt 10)

## Organisation model

An organisation can own multiple independently marketed property records. Each property has its own slug, listing status, pricing, media, room/unit records and future subscription relationship. The property `organisation_id` foreign key is enforced by the Prompt 10 migration.

Provider owners can update the organisation profile, see team members, create invitation links, and remove staff. Staff can work with organisation properties and enquiries but cannot edit organisation settings or invite/remove members. Invitation links are single-use, expire after seven days, and are accepted only by a signed-in account with a verified email matching the invitation address. The link is generated by the server and only its SHA-256 hash is stored. Email delivery is not configured; the owner copies and shares the link manually.

## Listing workflow

- Providers can create incomplete drafts and edit their own organisation's property records.
- A readiness meter checks ten core listing details.
- Submitting a draft or returned listing changes it to `pending_review`; it does not approve it.
- Providers cannot set approval or verification status themselves.
- Editing an approved listing returns it to `pending_review` so material changes are reviewed before being republished.
- Deleting a property cascades to its associated room/unit/media/enquiry records according to the existing foreign-key rules.

## Distinct inventory concepts

`property_room_categories` describes room TYPES (for example, Standard Double or Executive Suite). `property_apartment_units` describes individually managed apartment units. They are maintained through separate forms and database tables.

## Media and subscription notes

The gallery currently stores HTTPS image/video URLs in `property_media`. Direct file upload, storage bucket policies, and enforcement of the Starter/Professional/Premium media limits require the later storage/billing integration. The subscription overview is intentionally read-only and reports that billing is not connected in this stage.

## Enquiries and analytics

Providers can view and update the status of enquiries received for their own organisation's properties. Dashboard metrics are computed from real property and enquiry records. Enquiries and contact clicks are not reservations or bookings. No booking calendar or guest payment flow is included.

## Security

Server actions verify the signed-in provider role and re-check the property/organisation relationship. Supabase RLS remains the final permission boundary for properties, child records, organisation profiles, memberships, invitations and enquiries. The server never uses a service-role key for provider dashboard operations.
